# Solar PV + EV Charging + Battery Storage on the IEEE 33-Bus Distribution Feeder

A reproducible quasi-static (24-hour) power-flow study in Python / [pandapower](https://www.pandapower.org/) that asks:

> How do distributed solar PV and EV charging hubs change voltage, losses and line loading on a radial distribution feeder, and what can a battery do about it?

**Status:** student portfolio project. Network data are published (Baran & Wu, 1989). **Load, PV and EV profiles and all DER sizes are synthetic assumptions**, not measured data. Results describe this model under these assumptions only.

## Scenarios (cumulative)

| ID | Description |
|---|---|
| S0 | Base feeder, no DER, no EV |
| S1 | S0 + 4 PV sites (4 x 500 kWp = 2 MWp) at buses 6, 14, 24, 30 |
| S2 | S1 + 4 EV charging hubs (4 x 250 vehicles x 12 kWh/day = 12 MWh/day) at buses 8, 18, 25, 33 |
| S3 | S2 + one battery (1 MW / 4 MWh) at bus 18 with a fixed-window schedule: charge 11:00-14:00, discharge 19:00-22:00 |

### What the numbers say (for this model and these assumptions)

- **Base feeder** already breaches 0.95 pu at its weak end at peak (min 0.9131 pu at bus 18). This is a known property of the benchmark, and our base case reproduces the published 202.7 kW loss.
- **PV (S1)** cuts daily network losses by about 23% and imports by about 19%, but gives **no relief at 18:00-22:00** because PV output is zero then. No overvoltage at 2 MWp.
- **EV charging (S2)**, concentrated in the evening, is the dominant stress: min voltage drops to 0.8607 pu, peak substation import rises about 41% and peak loss about 2.1x versus S0.
- **Battery (S3)** lowers peak import by about 10%, peak loss by about 20% and the most loaded line from 96.8% to 84.7% of the assumed rating, and lifts voltage at 19:00-20:00 from 0.8607 to 0.8984 pu. **But** with this naive schedule it does not reduce daily network losses, adds about 300 kWh/day of conversion losses, and **creates new midday undervoltage** (about 0.875 pu at 11:00-13:00) because it charges at the weak end of the feeder. Dispatch and siting need to be voltage-aware, not just time-window based.

## Quick start

```bash
git clone https://github.com/EngAlruwili/ieee33-solar-ev-bess.git
cd ieee33-solar-ev-bess
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python main.py          # runs scenarios, sensitivity, validation, writes results/ and figures/
pytest -q tests         # validation tests
```

Python 3.10+ recommended. `numba` is optional (faster power flow): `pip install numba`.

If `pandapower` fails to install, use the free alternative [PYPOWER](https://pypi.org/project/PYPOWER/) (`pip install PYPOWER`) or [pandapower in a conda env](https://pandapower.readthedocs.io/en/latest/about/install.html); the model structure in `src/network.py` transfers directly.

## Key assumptions (all in `src/config.py`)

| Item | Value | Type |
|---|---|---|
| Feeder data, 12.66 kV, 3715 kW + 2300 kvar peak | Baran & Wu (1989) | Published data |
| Voltage limits | 0.95 - 1.05 pu | Planning convention |
| Line thermal ratings | 1.5 x base peak current, rounded up to a catalog size | **Assumption** (original data has none) |
| Load / PV / EV hourly shapes | synthetic | **Assumption** |
| PV, EV, battery sizes and locations | see table above | **Assumption** |
| PV inverters | unity power factor, no Volt-VAR | **Assumption** |
| EV chargers | power factor 0.98, no vehicle-level randomness | **Assumption** |
| Battery | 90% round-trip, SOC 10-90% | **Assumption** |

## Limitations

Single day, deterministic, balanced single-phase equivalent; no tap changers or capacitors; no inverter control; no uncertainty; battery schedule is not optimised; ratings are assumed. See [`docs/PROJECT_REPORT.md`](docs/PROJECT_REPORT.md) for the full list and future work.

## Validation

`python main.py` and `pytest` check that (1) total load is 3715 kW / 2300 kvar, (2) the base case reproduces the published loss (202.7 kW) and minimum voltage (0.9131 pu at bus 18), (3) results match pandapower's bundled `case33bw`, (4) hourly active-power balance closes to below 1e-6 MW, (5) battery power and SOC stay within limits.
